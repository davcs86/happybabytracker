# Growth Implementation Plan (plan 4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A parent records weight, length/height and head circumference per kid, sees each measurement's z-score and percentile under the kid's chosen reference source (WHO or CDC), with corrected age for preterm kids, and reads weight, length/height, head-circumference and BMI charts of the kid's points over the source's percentile curves.

**Architecture:** One migration adds `growth_measurements` and `kids.growth_source`. A new Go package `api/internal/growth` embeds the WHO and CDC LMS tables (compact CSV with provenance headers), computes z-scores, percentiles and percentile curves at read time; nothing stored depends on the source. Measurements are a date-based tracker with their own CRUD routes beside the six instant trackers; the UI gets a Growth page with hand-written SVG charts (no chart dependency), measurement forms, a source select in kid settings and a corrected age next to the age.

**Tech Stack:** Go 1.27 (`encoding/csv`, `math`, `embed`), SQLite via `modernc.org/sqlite`; SvelteKit 3 / Svelte 5 runes, Tailwind 4, inline SVG. No new Go or npm dependency.

**Spec:** `docs/superpowers/specs/2026-11-20-happybabytracker-design.md` sections 2 (G4, G13), 6.1–6.3, 7.1, 7.2, 8, 13.3, 14, 16. Earlier plans: `docs/superpowers/plans/2026-11-20-foundation.md`, `docs/superpowers/plans/2026-11-22-daily-trackers.md`. Research behind the data choices (retrieved 2026-11-22) is summarised in "Reference data" below.

## Global Constraints

- Every limit, cap and duration lives in `api/internal/constants/constants.go` (API) or `ui/src/lib/server/constants.ts`, with client-safe mirrors in `ui/src/lib/constants.ts` (CLAUDE.md rule 7). No literal elsewhere.
- A measurement stores its metric value, its imperial value and the unit typed, converted in one Go package only at save and edit; percentiles read the metric columns only (spec 6.2). Weight: grams and hundredths of an ounce; length and head circumference: millimetres and hundredths of an inch.
- Dates are `YYYY-MM-DD` in the kid's zone (rule 8, spec 6.1); a measurement has a date, not an instant.
- "Nothing stored depends on the growth source": z-scores, percentiles and curves are computed at read time; changing the source re-draws everything (spec 8.2).
- "A percentile or schedule is computed from reference data whose origin and version are not recorded" is an anti-goal: every table file records origin URL, version, retrieval date, licence and the SHA-256 of the file it was converted from (spec 8.1); a test checks each table against worked examples published by its source.
- The app records and displays; it never interprets a percentile (spec 2 non-goals): no "normal", "low", "concern" wording anywhere.
- Wherever corrected age is used the screen shows both ages (spec 7.1). Vaccination (plan 5) always uses chronological age.
- A caller with no grant, an unknown kid and an entry of another kid answer the same 404 body; the admin is refused; hard deletes; writes re-assert the role with `actorRole` inside `inTx` (as the six trackers do).
- Logs carry ids and enumerated facts only: never a value, a note, or a date of birth (rule 5, spec 13.3).
- Comments state constraints only, at most 2 lines (rule 9). `gofmt -l` prints nothing; staticcheck clean; Prettier tabs; every new page works without JavaScript, passes axe at 390×844 and 1280×800, and keeps `Cache-Control: no-store`.
- Embedded data lives under `api/internal/growth/data/` (never a directory named `testdata`, never a `*.db*` name: `api/.dockerignore` drops those). The WHO files carry their own `LICENSE` and `NOTICE`; the code stays MIT unless the owner decides otherwise (Open value 1).
- Tests that pin counts change together with the code they pin: `wantTables` and `schema_version` (`"3"`), the kid JSON key set (8 → 9 keys) in `kids_test.go`, `routeClasses`, `matrixParams`, `shell.spec.ts` (nav links), `quick-log.test.ts`, the stub's `KID_FIELDS`.

## Review Focus

Failure modes the spec implies that no task's happy path exercises; each has a test in the named task.

1. Corrected age edges: born at 36 weeks 6 days (corrected) vs 37 weeks 0 days (not); a measurement the day before and on the second birthday; corrected age below zero (before expected term) is listed unscored, never an error or a wrong number (Tasks 4, 6).
2. Table seams and gaps: WHO days 730/731 and 1856/1857, CDC 23.99/24 months, a head circumference at 6 years, WHO weight at 12 years, CDC BMI at 18 months: "not covered", never an extrapolated value (Tasks 3, 6, 7).
3. Unit exactness: 8 lb 3.5 oz typed keeps exactly `13150` hundredths of an ounce (3728 g derived); editing only the note re-sends nothing and rewrites no column; 0, negative and huge amounts are refused (Tasks 1, 6).
4. Changing the growth source changes every score and curve and no stored row; a kid created before this migration reads as the default source (Tasks 5, 6, 7).
5. Measurement dates: in the future (kid-local today), before the birth date, two rows on one date, a row with only one measure, a PATCH that would leave no measure at all, another kid's entry id (Task 6).

## Task 4: Age arithmetic and corrected age

**Files:** Modify `api/internal/kidtime/kidtime.go` (+ `_test.go`).

**Interfaces — Produces:**
```go
type AgeBasis struct{ ChronologicalDays, ScoringDays int; Corrected bool }
// Days between two YYYY-MM-DD dates in the kid's zone (on before birth is allowed and gives negative days).
func AgeDays(birthDate, on string, loc *time.Location) (int, error)
// Days a preterm kid is "early": 280 − (weeks*7 + days) when gestation is below 259 days, else 0; nil weeks or days → 0.
func CorrectionDays(gestWeeks, gestDays *int) int
// ScoringDays = ChronologicalDays − CorrectionDays while `on` is before the second birthday (birth date + 2 calendar years); Corrected is true when a correction was applied. A negative ScoringDays is returned as is (the caller decides what "before term" means).
func AgeBasisOn(birthDate string, gestWeeks, gestDays *int, on string, loc *time.Location) (AgeBasis, error)
// The birth date moved later by CorrectionDays ("the date the kid was due"), "" and false when no correction applies on `on`. The UI formats the corrected age with its existing age formatter from this date.
func CorrectedBirthDate(birthDate string, gestWeeks, gestDays *int, on string, loc *time.Location) (string, bool, error)
```
