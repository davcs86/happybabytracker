# Sickness, Medication and Reminders Implementation Plan (plan 6, app side)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Parents log symptoms (a fever with its temperature), keep medication courses with a schedule, log doses, and get a generic reminder ("Medication due for <kid>") on every device or ntfy topic they opted in for that kid, when the server has Web Push or ntfy configured. The home "Due" list and each course's "next due" read the same reminder rows the worker sends from, and work with no channel configured at all.

**Architecture:** Migration 0006 adds the symptom, medication, dose, reminder, delivery, push and ntfy tables and one kid column (`reminder_overdue_minutes`). A pure schedule engine (`api/internal/schedule`, imported by the store and the worker) lists a course's occurrences in the kid's zone. The store keeps, for every active scheduled course, a `reminders` row for each occurrence due in the last 30 minutes and for the next one ahead (unique on medication and due time); course, dose and kid-zone writes adjust those rows in their own transaction. A stdlib-only Web Push package (`api/internal/push`, from the tested prototype in the research notes) and a small ntfy publisher (`api/internal/ntfy`) deliver; each channel is on only when configured (VAPID optional since the owner's answer of 2026-11-23, ntfy optional as before). One worker goroutine (`api/internal/reminders`) ticks every 30 s: it materialises rows, creates one delivery per allowed target of each configured channel when a reminder falls due, sends each target on its own and settles it. The UI adds the sickness tracker, the medication screen, the kid's overdue setting, an account notifications screen, a service worker (install, push and notification click only) and the medication entries of the home Due list.

**Tech Stack:** Go 1.27 (`crypto/ecdh`, `crypto/ecdsa`, `crypto/hkdf`, `crypto/aes`, `crypto/cipher`, `net/http`), SQLite via `modernc.org/sqlite`; SvelteKit 3.1.1 / Svelte 5 runes, Tailwind 4, a SvelteKit service worker. No new Go or npm dependency (Open value 6).

**Spec:** `docs/superpowers/specs/2026-11-20-happybabytracker-design.md` sections 2, 5.2, 6.1–6.4, 7.2–7.3, 10.2, 10.3, 11, 11.1, 13.1–13.3, 14, 16. **This plan supersedes two spec lines by owner decision (2026-11-23):** 11 and 13.1's "the VAPID variables are always required" (now optional, both or neither) and 11's "without a connection the app shows an offline page" (deliberately not built). Task 24 updates the spec text. Earlier plans: `docs/superpowers/plans/` (foundation, daily trackers, growth, vaccination, advanced logging). Research notes (2026-11-22, rechecked 2026-11-23): `docs/superpowers/research/reminders/{web-push,ntfy-and-edge}.md` and the stdlib prototype `docs/superpowers/research/reminders/pushproto/*.txt` (its three tests pass on Go 1.27.0 as of 2026-11-23; rename to `.go` when copied into `api/internal/push`).

**Not in this plan:** anything in `davcs86/homelab-edge`, a separate plan and PR whose `CLAUDE.md` binds it. Plan 6 deploys with the edge unchanged: no `VAPID_*` and no `NTFY_*`, so both channels are off on the edge and reminders show only in the app (Due list, medication screen). A small edge PR rendering `VAPID_PRIVATE_KEY` and `VAPID_SUBJECT` (= `PUBLIC_ORIGIN`) turns Web Push on; the owner allows it to merge before or after the plan-6 bump (Open value 1). Tests and smoke use `HBT_ALLOW_FAKE_PUSH=1` for delivery.

## Global Constraints

- Every limit, cap, duration and tick lives in `api/internal/constants/constants.go` (API) or `ui/src/lib/server/constants.ts`, with client-safe mirrors in `ui/src/lib/constants.ts` (CLAUDE.md rule 7). No literal elsewhere.
- Instants are unix seconds UTC in INTEGER columns and RFC3339 UTC on the wire (rule 8). Fixed times of day are `HH:MM` in the kid's zone. "Every N hours" is a fixed grid from the course's start instant and is **never re-anchored to the last dose logged** (spec 10.3, owner); the app never computes or suggests a safe interval.
- Go's `time.Date` picks either side of a daylight-saving transition without a guarantee (its documentation says so). The schedule engine resolves a wall time explicitly: a time in a spring-forward gap fires at the first valid instant after it, a time in a fall-back overlap fires once at the earlier instant. It never builds local midnight with `time.Date` (the HANDOFF's midnight-DST flaw in `kidtime.BandStart` and friends must not spread here).
- **Each channel is optional and independent.** Web Push is on only when both `VAPID_PRIVATE_KEY` and `VAPID_SUBJECT` are set; ntfy only when `NTFY_URL` is set. With neither, the API starts, the worker still materialises, expires and marks reminders, and the Due list and medication screen work. A half-set channel is a start error naming the variable, never its value.
- The notification text is generic and fixed: `<Category> due for <kid's name>` ("Medication due for Mia"); it **never names the medication or the dose** (owner). It is built once, in Go, and sent as the push payload's `title` and as the ntfy title and message. The push payload is encrypted (RFC 8291) and carries only `{v, category, kid, title, path, tag}`.
- Logs carry ids (kid, parent, medication, reminder, delivery, device) and enumerated facts (channel, outcome, status class, attempt, duration, whether a channel is on) only: never a name, medication name, dose, note, temperature, push endpoint, push key, ntfy topic, token or key (spec 13.3, rule 5). A push endpoint is a secret-like capability: never in a log, an error string, a URL or an API response.
- A caller with no grant, an unknown kid and an entry of another kid answer the same 404 body; the admin is refused; writes re-assert the role with `actorRole` inside `inTx`; hard deletes; no edit history. Symptoms, medications, doses and per-kid opt-ins are class `Caregiver`; devices and the ntfy topic are class `Parent`; the kid's overdue setting rides the existing `PATCH /v1/kids/{kid}` (class `Guardian`). No request creates or edits a reminder row directly.
- **Delivery is decided at send time:** a reminder goes only to targets whose parent is enabled, holds a grant on the kid, and opted that target in for that kid, while the kid's `medication` module is on, the course is active and within its dates, and the target's channel is configured. A row materialised earlier never overrides this (spec 11, 14).
- Two windows, two constants: `ReminderExpiry` (30 min) bounds **delivery** (no send later than due + 30 min); the kid's `reminder_overdue_minutes` (default 60, 5–1440) bounds how long a missed dose shows `overdue` on the **home Due list**. Neither reads the other.
- Reads that combine a row and its children, or a course and its reminders, use one `Store.inReadTx` snapshot through `querier` (plan 5.1). Lists load children with one extra query per page, never one per row.
- Measured values are stored three ways (spec 6.2): a temperature as hundredths of °C, hundredths of °F and the unit typed, converted only in `api/internal/units`. A PATCH merges onto the stored row; an unchanged typed value in the same unit keeps the three stored columns, and that comparison runs **before** the range check, so an unchanged stored value never becomes invalid (`mergeVolume`, `mergeWeight`, `changedOK` are the pattern).
- UI form readers send only what changed, against hidden `*_original` fields, and fail closed on a missing original (plan 5.1). The UI converts nothing: it formats the API's columns. Units come from `formUnits(session)`.
- The stub API (`ui/e2e/stub-api.ts`) mirrors each Go handler's validation order, field names and 404 rules line by line; UI tests are green on a broken contract, so `scripts/smoke.sh` is the real check (CLAUDE.md "How to Act" 4).
- **Every Playwright form save waits for its response with `submit()` from `ui/e2e/helpers.ts`** (a click-then-assert race flaked CI in plan 5).
- `Cache-Control: no-store` on every page that shows kid data (already global in `hooks.server.ts`); every new page except the push enable button works without JavaScript and passes axe at 390×844 and 1280×800; comments state constraints only, at most 2 lines (rule 9); `gofmt -l` prints nothing; staticcheck clean; Prettier tabs.
- Tests that pin counts change with the code they pin: `wantTables` and every `schema_version` assertion in `api/internal/store/store_test.go` (Task 1 lists them); the kid JSON key set in `api/internal/httpapi/kids_test.go` (Task 3 lists the places); `routeClasses`, `matrixParams` and the fixture in `api/internal/httpapi/matrix_test.go`; `store.TimelineTypes` and `timelineModules`; the home `due` entry key sets (`home_test.go`); `TRACKER_KINDS`/`TRACKER_ROUTE`/`TIMELINE_TYPE`/`TRACKER_TITLE`/`TRACKER_LABEL` and `quick-log.test.ts`; the `tracker` param matcher test; the stub's kid view.

## Reference data (what the research found; verify by test, do not re-research)

- **Web Push in Go, stdlib only**: the prototype (`pushproto/push.go.txt`, 153 lines) passes the RFC 8291 Appendix A vector byte for byte, an independent decrypt round trip and a VAPID test; rerun on Go 1.27.0 on 2026-11-23: `PASS` (3 tests). Facts: P-256 ECDH, HKDF-SHA256 (`crypto/hkdf.Key`), AES-128-GCM, one record, `rs` 4096, plaintext cap 3993 bytes; headers `Content-Encoding: aes128gcm`, `TTL` (required), `Urgency`, optional `Topic` (≤ 32 of `[A-Za-z0-9_-]`, replaces a pending message with the same topic), `Authorization: vapid t=<jwt>, k=<65-byte public key b64url>`. The ES256 JWT signature is **raw 64-byte r||s** (not DER); `aud` is the endpoint's origin; `sub` the `https:` subject; `exp` ≤ 24 h (RFC 8292). The edge generates the private key as 43-character unpadded base64url (`init_secrets.py::generate_vapid_private_key`, checked 2026-11-23); parse with `ecdsa.ParseRawPrivateKey(elliptic.P256(), d)` after requiring 32 decoded bytes; the public key is `.ECDH()` → `.PublicKey().Bytes()` (65 bytes). `webpush-go` v1.4.0 adds `golang-jwt/jwt/v5` and pads every message to 4096 bytes: not chosen.
- **Statuses**: 201 accepted; 404/410 gone (delete that subscription); 429 (honour `Retry-After`) and 5xx/timeout/network retry; 400/401/403/413 and other 4xx: configuration or payload fault, never retried for that occurrence, subscription kept (a rotated VAPID key shows as 401/403 on every subscription).
- **xstockstrat `services/xstockstrat-notify/src/fanout/webPush.ts` (read 2026-11-23):** copy TTL 3600 s, 10 s timeout, prune only on 404/410, always show a notification on push, a deterministic `tag`, the public key served by the server, and "the channel is disabled, not crashed, when VAPID is missing" (now matching the owner's answer). **Do not copy:** no retries, sequential sends, no endpoint validation (SSRF), an upsert that silently re-binds a subscription to another user and an unscoped unregister, a payload carrying the alert text, a loose `includes` click match.
- **iOS**: Web Push exists only for a web app added to the Home Screen (iOS/iPadOS 16.4+, manifest `display: standalone`, already set) and the permission request must follow a user gesture (WebKit blog 13878). Apple's push service answers 403 `BadJwtToken` when the JWT `sub` "isn't a URL or mailto:"; one public report saw Apple reject a reserved `.local` subject. The edge's subject would be the tailnet-only `https://happybaby.private.<domain>`: Apple's acceptance is **not verified** (needs a real iPhone).
- **SvelteKit 3.1.1** (checked in `node_modules` 2026-11-23): `$service-worker` was removed (`module_removed_service_worker`); use `$app/manifest`, `$app/env`, `$app/service-worker`. `src/service-worker.ts` (or `src/service-worker/index.ts`, the form Task 21 uses) is auto-registered at scope `/` as a module worker; the Node adapter serves `/service-worker.js` before the hooks (`e2e/pwa.spec.ts` proves the static path). There is no CSP. Playwright (Chromium) can cover a stubbed `PushManager` and a dispatched `PushEvent`; real delivery, iOS and Apple's acceptance of the subject need a real device.
- **ntfy**: JSON publish to the server root (`topic`, `message`, `title`, `click`) with `Authorization: Bearer tk_…`; 4096-byte message limit; per-visitor rate limit 60 burst, 1 per 5 s; a topic nobody subscribes to caches the message (72 h on the edge). On the edge the API cannot reach ntfy today (API on network `happybabytracker` only, ntfy on the default network), `NTFY_URL` would be `http://ntfy:2586` (the app must accept `http:`), and only `david` reads topics under `deny-all` (edge-plan matters, E1–E2).

## Review Focus

Failure modes no task's happy path exercises; each has a test in the named task.

1. **Clock edges.** A fixed time inside the spring-forward gap (`America/New_York` 02:30 on the change day fires 03:00 EDT), a fixed time in the fall-back overlap (01:30 fires once, at the EDT instant), a zone whose DST starts at midnight (`America/Havana`, `America/Santiago`: a 00:00 time and `end_on` both land correctly), a course starting mid-day, one ending today, one with `end_on` before today, a leap day and 31 Dec → 1 Jan; a kid's time-zone change re-materialises fixed-time rows (Tasks 5, 6).
2. **Restart and concurrency.** A restart or a second tick mid-send: no duplicate occurrence, no duplicate delivery to a target that already accepted, a row left `sending` becomes `unconfirmed` and is never resent; one hanging target does not delay another past the timeout, one failing channel never blocks the other (Tasks 12, 13).
3. **Access after materialisation.** Grant revoked, parent disabled, module switched off, course made inactive or deleted, the kid deleted, a dose logged 29 minutes early, 1 minute before the push, or for the previous occurrence: nothing is sent where nothing may be, and a dose marks exactly one occurrence done (Tasks 7, 10, 12, 13).
4. **Hostile subscriptions.** `http:`, a userinfo URL, a non-443 port, an IP literal, `localhost`, a hostname resolving to a private, loopback, link-local or ULA address (at registration **and** at dial time), a redirect, a compressed or invalid `p256dh`, an `auth` not 16 bytes, an endpoint over 2048 bytes, the same endpoint registered by a second parent, 404/410 deleting only that subscription, 429/5xx retried but never past the 30-minute expiry (Tasks 9, 10, 13).
5. **Input edges.** Temperature 0, negative, below 30.00 °C or above 45.00 °C (and the °F equivalents ±1 hundredth), a decimal comma, three decimals; a name or dose text of 81 characters; every-N-hours 0 or 169; 13 fixed times, a duplicate time, `24:00`, `7:5`; `end_on` before the start; a dose more than 5 minutes in the future; a dose for another kid's course; `reminder_overdue_minutes` 4, 1441, `"60"`, `null`, 60.5; a PATCH that only changes the note keeps every stored column (Tasks 2, 3, 4, 6, 7).
6. **Channel configuration.** Neither channel, Web Push only, ntfy only, both; only one of the two VAPID variables; `HBT_ALLOW_FAKE_PUSH=1` without VAPID; push routes while Web Push is off; a device registered while on, then the server restarted with VAPID unset: no delivery row, no send, the device still listable and removable (Tasks 8, 10, 13, 22, 24).
7. **Due list.** Medication entries and vaccine groups share `HOME_DUE_MAX`; vaccine-only behaviour is byte-for-byte unchanged when a kid has no course; a missed dose stays `overdue` until due + the kid's minutes **or** the next occurrence, whichever comes first (a 1-hour course with a 1440-minute setting shows one overdue entry, never 24); never for a module that is off or an inactive course (Tasks 15, 23).

## Changes from the draft

1. Migration `0005_sickness_medication.sql` → `0006_sickness_medication.sql`; `schema_version` `"5"` → `"6"` in five assertions (plan 5.1 took 0005). 0006 also adds `kids.reminder_overdue_minutes`, so the kid JSON key set grows from 10 to 11.
2. **VAPID is optional** (owner, 2026-11-23, superseding "always required"): both or neither; Web Push off answers `{"enabled":false}` and 409 `push_unavailable` on writes; the worker, the Due list and the medication screen work with no channel. Plan 6 deploys with the edge unchanged; the edge's VAPID PR turns Web Push on (the first refresh's "edge must go first" constraint is gone).
3. **Materialisation:** the draft materialised only `now − 30 min .. now + 2 min`, which left nothing for "next due" and the home Due list to read (spec 11 says both read the reminder rows); now the next occurrence is always materialised and course, dose and kid-zone writes adjust rows in their own transaction (Open value 14).
4. The schedule engine moved from `api/internal/reminders` to `api/internal/schedule`: the store needs it, and the worker imports the store (an import cycle otherwise).
5. **Done rule:** the draft's window let one dose mark two occurrences done; now it marks exactly one (Open value 15).
6. Per-kid opt-in routes moved under `/v1/kids/{kid}/…` with class `Caregiver` (the draft's `/v1/me/…/kids/{kid}` under `Parent` could not give the grant 404 through the middleware, and the matrix would fail); `/v1/me/push-subscriptions` renamed `/v1/me/push-devices` and gained a label PATCH; `GET /v1/push/public-key` became `GET /v1/push` with `enabled`.
7. `/healthz/reminders` is class `Open` like `/healthz` (the draft said internal-token, which Gatus through the UI could not call); its 503 condition is defined (Open value 30).
8. The band-crossing change in the draft's Task 9 is dropped: `sickness` and `medication` are on in every band (`store.DefaultEnabled`).
9. Medication doses are not a timeline type (owner): the UI's timeline is keyed on `TrackerKind` and doses have no log route; symptoms join as `TrackerKind` `symptoms` / type `symptom`.
10. `units.NewTemperature` does not exist yet and is its own task; units `c`/`f` match the profile's existing `temp` preference; the UI accepts two decimals in both units.
11. A course has one `start_at` instant instead of a `start_on` date plus a separate grid start.
12. The payload carries a server-built `title` (one source of the generic text for push and ntfy) instead of the service worker composing it; delivery states gained `gone` and `cancelled`, and deliveries a `parent_id` and `settled_at`.
13. Home Due: `dueView` becomes a union so vaccine entries keep their four keys; the shared `HOME_DUE_MAX` cap and per-kind "more" lines are defined; the overdue window is the kid's `reminder_overdue_minutes` or the next occurrence, whichever comes first (owner), separate from the 30-minute delivery expiry.
14. **No offline page** (owner): the service worker handles install, push and notificationclick only; spec 11's offline page is deliberately not built; `/offline.html` and the navigation `fetch` handler are dropped.
15. The draft's 15 tasks are 24: API and UI split further (temperature units, the kid setting, push crypto vs sender, reminder store vs worker, health, UI plumbing in two, the settings field, service worker vs notifications page).
16. ntfy-off writes answer 409 `ntfy_unavailable` (the draft and the first refresh said 404), matching Web Push.
17. Global Constraints and Review Focus fold in plan 5.1's lessons (`inReadTx`, unchanged-before-range, PATCH merges, `*_original`, `formUnits`, `submit()`, the stub mirroring handlers) and the HANDOFF's midnight-DST flaw.
