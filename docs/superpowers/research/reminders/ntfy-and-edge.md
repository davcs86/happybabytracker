### Reachability answers
- Publish over the compose network, not the public URL: the `ntfy.private...` name has no public DNS and resolves only via the tailnet split-horizon (headscale extra-records), so a container (host resolver, no tailnet DNS) cannot rely on it, and going through Caddy needs the edge cert and 443 hairpin. Use `http://ntfy:2586` on a shared network.
- Today the API container is **not** able to reach ntfy (API on `happybabytracker` only; ntfy on the default network). A shared network is required.
- `NTFY_PUBLIC_URL` (https://ntfy.private.natanddavehouse.com, = ntfy `base-url`, what the parent types into the iOS/Android app) differs from `NTFY_URL` (http://ntfy:2586). So the optional PUBLIC var is mandatory on the edge. Click target should be `PUBLIC_ORIGIN` (the app), unchanged.

## 3. ntfy facts (docs.ntfy.sh/publish, /config; fetched 2026-11-22)
- Header publish: `POST /<topic>` with body = message; headers `Title` (alias X-Title/ti/t), `Priority` (X-Priority/prio/p; 1-5, 3 default), `Tags` (X-Tags/tag/ta), `Click` (X-Click), `Authorization: Bearer tk_...`; also `Cache: no`.
- JSON publish: POST/PUT to the **server root** `/` (not the topic URL) with `{"topic","message","title","priority":int,"tags":[...],"click":url,"actions":[...],...}`; only `topic` required; empty message becomes "triggered". JSON avoids header encoding issues for non-ASCII kid names; headers with non-ASCII need RFC 2047 encoding, so prefer JSON (or UTF-8 body + ASCII-only title).
- Auth: `Authorization: Bearer tk_...`; or Basic with empty user and token as password; or Basic user:pass; or `?auth=<base64 of the Authorization value, unpadded>`. Tokens are `tk_` + 29 chars (32 total).
- Message limit 4,096 bytes (longer becomes an attachment; irrelevant for a one-line reminder); title <= 1 KB, all tags <= 512 B combined, violations are HTTP 400.
- Rate limits per visitor (IP; with `behind-proxy` the IP comes from X-Forwarded-For): 60 requests burst, refill 1 per 5 s (`visitor-request-limit-burst/replenish`). All API publishes come from one container IP = one visitor: ample for a family, but a retry storm after an outage is bounded at ~12 req/min sustained; the worker should batch/back off. Docs do not say what ntfy does when behind-proxy is on and the header is missing; existing internal publishers prove it works on 127.0.0.1 (verify from the API container's address).
- Topics are created on the fly by publish or subscribe. A topic nobody subscribes to simply caches the message (edge: 72h) and a later subscriber with `since=` (the app does this) receives it; publish returns 200 regardless. With deny-all, publish to a topic outside the user's ACL is 403 (the design's "401/403 = configuration fault").
- Reading: with `auth-default-access: deny-all` only admin (david) and users with an ACL can subscribe. Another parent needs an ntfy user with `ro` on exactly their topic (declared by hand in ntfy-server.yml.j2); the topic is random per parent and regenerable, so a static ACL cannot name it: ACL on `<prefix>-*` read-only would let that user read every parent's topic. Open question for the owner (see 5).
- iOS: the self-hosted server needs `upstream-base-url: https://ntfy.sh` (present) so ntfy sends a poll request carrying only the message ID and SHA-256 of the topic URL to ntfy.sh/APNs; the app subscribes to the hashed topic under the server URL it was added with, so the subscription must use the server's `base-url` name (the docs page itself does not state the matching rule; the edge's decisions.md:103-106 and the HANDOFF do). Without it iOS delivery takes up to hours. Android works without upstream but "instant delivery" needs the foreground service.
- Default cache is 12h, edge sets 72h; messages are on disk in cache.db (`cache-file`), so the generic "<Category> due for <kid's name>" text rests there 72h (design L483-484).

## 4. Env contract vs. what the edge provides
| Var | Design | Edge would give | Note |
|---|---|---|---|
| NTFY_URL | publish target, unset = off | `http://ntfy:2586` (compose) | scheme is http, not https: app validation must allow `http:`; the app refuses malformed URLs |
| NTFY_PUBLIC_URL | optional, shown to parents | `https://ntfy.private.natanddavehouse.com` | required on the edge; must equal ntfy `base-url` |
| NTFY_TOPIC_PREFIX | 1-32 of a-z0-9- | inventory value (owner) | must match the ACL pattern `<prefix>-*`; ntfy topic chars allow `_` and uppercase too, app is stricter: fine |
| NTFY_TOKEN | optional secret | `tk_` + 29 [a-z0-9] from SOPS | on a deny-all server it is effectively mandatory; asserted single-quote-safe |
Discrepancies: (a) design L615 "generated only when enabled" vs unconditional `fill_missing` + CI keys test; (b) design says nothing about the shared compose network and the existing test that forbids other services on `happybabytracker`; (c) design lists Gatus probe `/healthz/reminders` through the UI: the UI route does not exist yet and the UI's host check must allow it; (d) design 15 says the readers are "nothing for readers: david reads every topic", which means only david can receive the reminders on a deny-all server; (e) VAPID_* rendering also lands in this edge change although the design's ntfy switch text does not mention it.
